# Audit 2026-10-04 — Silent Drops, Doc Drift, API Gaps

Made from the working tree of 2026-10-04 (after the uncommitted media-mapping change and
the removal of the pre-flight size check, see the spec §0). Line numbers are approximate
and refer to that working tree.

## A. Silent failures and drops

| Sev. | Finding | Evidence |
|---|---|---|
| High | Unknown response step types are ignored (`MapStep` has no fallback after `thought`). Unknown `model_output.content[].type` values are ignored (`MapModelOutputStep`). Audio/video output, `file_search` results and future types disappear without an error. | `GeminiInteractionsChatClient.cs` ~1133–1171, ~1208–1251 |
| High | Streaming: unknown SSE event types, unknown `step.start` types and unknown delta types are logged at Debug level and skipped. | `Internal/GeminiSseEventReducer.cs` ~61, ~133, ~279 |
| High | `MapFinishReason` maps only completed / requires_action / length / safety statuses; `failed`, `cancelled` and any other status become `null` without a log. A failed interaction can be reported as an ordinary completed turn. | `GeminiInteractionsChatClient.cs` ~1489 |
| High | Stream `error` events and `status_update` with status `error` become an `ErrorContent` update; the stream continues and no exception is thrown. CatHerder shows the error line but records the turn as completed (not retryable). | `Internal/GeminiSseEventReducer.cs` ~87–120 |
| Medium | `ChatOptions.ToolMode` (RequireAny / None / RequireSpecific) and `AllowMultipleToolCalls` are not mapped; the API has `tool_choice`. | `MapTools`, `Internal/GeminiInteractionsRequestModels.cs` |
| Medium | `ChatOptions.Seed` is not mapped although the API has `generation_config.seed`. `FrequencyPenalty` / `PresencePenalty` have no API equivalent and are ignored instead of rejected. | `MapChatOptionsToGenerationConfig` ~911 |
| Medium | Text `annotations` (URL / file / place citations with byte ranges) are never read; grounded answers lose their sources. | no `annotations` in `src/` |
| Medium | Non-streaming `thought` steps/parts are only written to the Debug log (`LogThoughtSummary`); streaming surfaces them as reasoning content. | `GeminiInteractionsChatClient.cs` ~1168, ~1248, ~1346 |
| Low | Usage: per-modality token breakdown and grounding tool counts are not mapped. | `Internal/GeminiUsageMapper.cs` ~24 |

Not found: silent drops of *input* media (fixed in the working tree: unsupported input
content throws).

## B. Documentation drift and gaps

- README "Nothing is dropped silently" (added 2026-10-04) is true for input only; A
  contradicts it for responses.
- README "Audio is input-only" is ambiguous now that assistant-turn audio is sent as
  `model_output`; it means Gemini audio *output* is not mapped.
- Undocumented: built-in tool calls/results are left out when history is resent; which
  `ChatOptions` are ignored; that unknown stream events are skipped (README only says the
  SSE handling "may evolve").
- Google's May 2026 migration guide names `interaction.in_progress` /
  `interaction.requires_action` as replacing `interaction.status_update`; the client only
  handles `status_update` (the API reference still shows it). Needs a live check.
- `project-status-roadmap.md` "Last updated 2026-05-08" while describing later work.
- plan064 documents still describe the removed 20 MB pre-flight check (historical).
- plan060 (`plan060-interactions-fail-fast-schema-parsing`, old-format draft, never
  completed) asks the same two questions as this plan (unknown SSE events: Debug or
  Warning; stream errors: throw or `ErrorContent`).

## C. Interactions API features not supported

Sources: https://ai.google.dev/api/interactions-api-v1,
https://ai.google.dev/gemini-api/docs/interactions-overview,
https://ai.google.dev/gemini-api/docs/interactions-breaking-changes-may-2026

| Area | Not supported |
|---|---|
| Request | `tool_choice` (incl. `allowed_tools`), `seed`, `store`, `background`, `labels`, `agent` / `agent_config` |
| Input | Files API references, video input, image `resolution` |
| Tools | `file_search`, remote MCP (`mcp_server`), Computer Use |
| Output | image/audio/video `response_format`, `annotations` (citations), `file_search` results |
| Operations | GET interaction (incl. stream resume with `last_event_id`), DELETE, cancel, background polling, agents (Deep Research, managed agents) |
| Usage | per-modality breakdown, grounding tool counts |

Note: `store` is never sent, so every interaction is stored by Google (chaining through
`previous_interaction_id` depends on it) and none is ever deleted.
